## Performance regression and genuine repair

Parent isolated the cost to four filtered backdrop upscales; its finding is preserved unchanged in `docs/v1.1-parent-perf-finding.md`. The repair keeps all four independent 2048×540 authored planes and their original artwork/offset factors, composes them at CSS resolution into one reusable 960×540 or 720×540 Canvas, then smoothly blits that once to the unchanged DPR2-cap output. No layer merge/drop, disabled smoothing or lower DPR. One cached live MediaQueryList updates naturally on viewport/orientation changes; no new resize loop or per-frame query is needed.

Test replacement rationale: the former test's four blits directly to the target encoded the costly implementation detail. The replacement observes `CanvasRenderingContext2D.prototype.drawImage` across the real composition graph, restores the prototype afterwards, and requires four distinct authored-size images, identical cache identities between camera positions, exactly ordered offsets `[0, -600*.09, -600*.23, -600*.41]`, four zero quiet-mode offsets and twelve planes after 96 route cycles. It additionally requires exactly one smooth blit to the target on every sampled paint and a measured allocation bound. Stable pixels, quiet-time stable pixels and immutable snapshots remain mandatory. The old maximum dimensions are strengthened to exact 2048×540 plane dimensions, not relaxed. A separate native orientation test requires one narrow-query construction across repeated paints/resizes.

Genuine RED before renderer edits: `05-composite-red.txt` shows four target blits where one is required and 75 query constructions where one is required. `05-composite-green.txt` records both tests passing. `05-composite-harness.txt` preserves the initial IEEE754 exact-literal harness mismatch; its arithmetic expectation was corrected before the meaningful RED, not used as feature-failure evidence.

Own measurement command: `node artifacts/v11-perf-probe.cjs before` / `after`. The reproducible local probe drives the actual native app using the suite's fake clock, but times each `runFor(2000)` with Node's real monotonic clock and requires exactly 240 accepted ticks. Three samples per build/viewport, DPR2, headless Chromium with `--use-angle=swiftshader-webgl`, loopback-only HTML embedding the exact runtime. The v1.0 comparison uses `git show de7e75f:<file>`, never synthetic game responses. Raw samples: `artifacts/v11/perf-{before,after}.json` and `.log`.
